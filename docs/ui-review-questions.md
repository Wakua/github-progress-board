# UIレビューで必ず使う問い

画面を変更する担当者は、この一覧で点検し、PRの「UIレビュー」にIDと根拠を記録する。
学習メモの問いを、このリポジトリの提出時に使う形へ整理した。
問いのID・項目はCIもこの表から読む。
学習メモの全文や個人端末のパスは、提出の前提にしない。

| ID | 項目 | 問い | 整理元 |
| --- | --- | --- | --- |
| I1 | 情報量 | 今の判断や操作に不要な常設説明・重複を削れるか。削除前後で比較したか | 学習メモ01「美的で最小限のデザイン」、02「段階的な情報開示」 |
| I2 | 情報量 | 必要な情報を削っていないか。意味・条件・結果を推測したり、別画面の値を覚えたりせず判断できるか | 学習メモ01「再生より再認」、02「認知負荷」 |
| J1 | 判断の手掛かり | 対象・状態・関係と操作の入口を見分けられるか。色だけに意味を持たせていないか | 学習メモ02「操作の手掛かり」、03「色に依存しない情報伝達」 |
| J2 | 判断の手掛かり | 狭い画面や拡大時にも、必要な文字・数値・単位・操作部が欠けずに読めるか | 学習メモ03「拡大時の読みやすさ」 |
| O1 | 操作 | 必要な操作を実行し、結果を確認して次へ進めるか。変更に関係する空・処理中・失敗の状態からも続けられるか | 学習メモ01「システム状態の可視性とフィードバック」、02「空の状態の案内」「変更の取り消しと復旧」 |
| O2 | 操作 | キーボードでも操作でき、詳細を閉じた後にフォーカス・選択・表示位置を保って作業を続けられるか | 学習メモ02「一覧と詳細の行き来」、03「キーボード操作とフォーカス」 |

変更に関係する追加の問いは、PRの表へ行を加える。
数値表示なら欠測値とゼロ・割合の分母、文言なら名称と実際の動作、利用者テストなら課題が操作場所や正解を教えていないかも確認する。
追加の問いにも判定と根拠を残す。

根拠では、情報量は削除・移動・保持した情報と判断との関係を、判断の手掛かりは画面から読み取れる事実を示す。
操作は手順・結果と、続けるために必要な状態を記す。
静止画での点検、実操作、実利用者の理解を区別する。

## 出典

整理元は共通のUI/UX学習メモの01〜03である。
補足を読む場合は各端末にあるメモのREADMEから該当節を選ぶ。
この一覧だけで確認できない条件があれば、未確認としてPRに記録する。

原則の背景は、[最小限のデザイン](https://www.nngroup.com/articles/aesthetic-minimalist-design/)、[認知負荷](https://www.nngroup.com/articles/minimize-cognitive-load/)、[キーボード操作](https://www.w3.org/WAI/WCAG22/Understanding/keyboard.html)、[色の使用](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html)、[リフロー](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)を参照できる。
これは提出前の点検項目であり、WCAG全体の適合や実利用者の理解を保証する一覧ではない。
