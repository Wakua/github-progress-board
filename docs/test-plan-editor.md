# テスト計画の作成・変更

ローカル版のテスト担当者向けに、対象版と実施条件を決め、ケースを選んで計画を保存する手順を示す。
結果入力とBug連携は含めない。
項目・状態・完了条件は[テスト管理の仕様](test-management.md#テスト計画)を正本とする。

## 起動と操作

[READMEの起動手順](../README.md#起動と検証)で起動し、テスト管理から「テスト計画」を開く。
直接開く場合は `/testing/plans.html` を使う。
クラウド版には入口・画面・保存APIを含めない。

1. 「＋ 計画を作る」で、計画名・対象バージョン・実施条件を入力する。
   実施条件はOS・OSバージョン・モデルの組を追加する。
2. 「ケースを選ぶ」でActiveのケースを個別、カテゴリ、表示中の一括選択で選ぶ。
   選択数×条件数を確認して「計画を作成」を押す。
3. 保存後は、ケースごとの担当、条件、対象版などを変更できる。
   完了・再開と変更前後の内容は「履歴・実施記録」から確認する。

一覧を閉じても作成中の入力とケース選択を保持する。
狭い画面では計画の選択後に一覧を閉じ、計画名へフォーカスを移す。
開閉設定・選択中の計画・未保存の入力は再起動後には復元しない。
保存した内容と履歴は再読込み・再起動後も保持する。

## 保存失敗と競合

保存中は重ねて操作できない。
保存に失敗したら入力を残し、「再試行」で同じ内容を送る。
同時編集の競合では、保存済みの内容をその場で開いて比較できる。
必要な入力を控え、「入力を破棄して再取得」で最新の計画へ戻る。
自動統合や強制上書きは行わない。

作成中に別の計画へ移るときは、入力の破棄を確認する。
編集ダイアログのキャンセル・Escapeはその編集を取り消す。
ページを離れる際はブラウザーの確認を使う。
PCやブラウザーの終了時に、未保存の入力を復元する機能はない。

## 保存の内部契約

保存先、バックアップ、ローカルAPIの接続制限は[テストケースの保存](test-case-editor.md#保存と復旧)と共通である。
`plan-session.mjs`が受付キーを保持し、`plan-repository.mjs`がHTTPへ接続する。
`server/test-plan-store.mjs`が計画と履歴の保存を担当する。

| 操作 | API | 動作 |
| --- | --- | --- |
| 一覧 | `GET /api/testing/plans` | 計画、実施単位、変更履歴を一つの読み取りトランザクションで返す |
| 新規入力 | `POST /api/testing/plan-ids` | TP-IDを予約する。欠番は再使用しない |
| 保存・削除 | `PUT /api/testing/plans` | `values`、`revision`、`requestId`、`action`、`acknowledgeWarnings`を照合する |

DBの版1から版2へ、計画・実施単位・履歴・受付記録のテーブルを一つのトランザクションで追加する。
既存のケース、ケースのIDと受付記録は書き換えない。
移行失敗時はテーブル追加と版変更を戻し、APIは保存先を利用できないことを返す。
未対応のDB版は開かない。

保存では更新番号を照合し、計画・未実施の組・履歴・受付記録を同時に確定する。
同じ受付キーと同じ入力の再送は、記録済みの応答を返す。
後続の変更があっても、過去の再送でDBを戻さない。
受付記録の自動削除は行わない。

ケースの追加時点では定義をコピーせず、ケースIDを参照する。
ケース×実施条件ごとにNot Runを作り、実施者・実施日時はNULLとする。
結果入力APIと初回結果時のケース内容コピーは#172の対象である。
検証用の結果は専用DBへ直接配置した架空記録であり、製品の結果登録機能ではない。

除外可能な未実施の組は削除するが、変更前後のケースID・条件を履歴に残す。
記録済みの条件はIDの差替えや内容変更も保存側で拒否する。
下書き計画の削除は一覧から隠す論理削除であり、計画・実施単位・履歴・ID・ケース定義を保持する。

一つの計画の上限は500ケース・20条件とする。
文字数は計画名など500文字、目的20,000文字、関連Issue2,000文字、条件とケース担当の各項目200文字までとし、未知の項目は拒否する。
HTTP本文の上限は共通APIに従う。

## 検証用の起動

```powershell
node --test tests/test-plan-store.test.mjs tests/test-plan-api.test.mjs
$env:TEST_PLAN_FIXTURE_DIR = '<Git管理外の専用フォルダー>'
$env:PORT = '4499'
node tests/test-plan-screens-server.mjs
```

専用フォルダーに架空のケースと、削除・結果保護・完了警告の確認用計画を初回だけ作る。
再起動時にはリセットせず、保存内容を読み込む。
通常の製品画面と実SQLiteを使い、既存の保存先には接続しない。
