# 進捗管理ツールの操作

## プロジェクトの登録

複数プロジェクトを登録し、次の作業・要対応・確認待ちを把握する進捗管理ツール。
プロジェクトを選ぶと、目標・作業・依存関係・成果の根拠を確認、編集できる。

手動入力と読み取り専用のGitHub snapshotを分けて保持する。
`npm start`のローカルモードは同じブラウザに保存する。
認証付きのクラウド共有保存も持つ（[クラウド共有保存](development.md#クラウド共有保存の実装と確認範囲)）。

初回は空の一覧を表示する。
複数のプロジェクトを名前とrepository URLで登録できる。
手動計画の進捗、Issue、担当者、見積、期限は自動で補わない。

ローカル起動時は、設定で指定したrepository（[ローカルのghで自動取得する](github-integration.md#ローカルのghで自動取得する)）からGitHubの目標・作業・期間・リリースとIssue・PRの状態を別領域へ自動取得できる。

集計テスト用の架空データは、通常画面には読み込まない。

## 画面の構成

画面は、人が知りたい問いごとに分ける。
規則は各節に書き、ここでは問いと節の対応だけを示す。

| 画面 | 答える問い | 仕様 |
| --- | --- | --- |
| 全体一覧 | どのプロジェクトで、次に何をするか・人の手が要るか | [プロジェクトと保存](specification.md#採用済み仕様プロジェクトと保存ローカルモード)の先頭 |
| 承認待ちのPR（プロジェクトの上部） | 人の承認が上限に達していないか | [承認待ちのPR](specification.md#承認待ちのpr) |
| ① 自分の作業（タブ） | 今日何をやるか | [自分の作業と要対応](specification.md#自分の作業と要対応)。GitHubで計画しているプロジェクトは[GitHubから表示する計画](specification.md#githubから表示する計画) |
| ② イテレーション（タブ） | 期間内に間に合うか | [イテレーションと期限](specification.md#イテレーションと期限)、[担当別の負荷](specification.md#担当別の負荷)、[表示ルール](specification.md#表示ルール) |
| 詳細（右のパネル） | なぜ止まっているか、何が終われば進むか | [操作](#操作)、[詳細での入力と移動](specification.md#詳細での入力と移動) |
| ③ 要対応（タブ） | どこで人の手が要るか | [要対応タブ](specification.md#要対応タブ試作)（試作）。行動の整理は[③④の行動の整理](attention-release-behavior.md) |
| ④ リリース（タブ） | リリースに間に合うか | [リリースタブ](specification.md#リリースタブ試作)（試作）。行動の整理は同上 |

GitHubで計画しているプロジェクトはGitHubの作業を表示し、手動の計画はGitHubのないプロジェクトに使う（2026-10-04 ユーザー決定）。

## 操作

- 上部の「登録・取込」で登録操作と選択したプロジェクトのGitHub snapshotを開く。
  「プロジェクトを登録」で名前と任意のrepository URLを入力し、「GitHub snapshotを読み込む」で取込を開始する。
- 上部の選択欄または全体一覧の「プロジェクトを開く」で表示を切り替える。
  再読み込み後も選択を復元する。
- プロジェクトを選び、「登録・取込」の「目標を登録」「作業を登録」で自分のデータを追加する。
  登録・取込の操作とGitHub snapshotの欄は、普段の作業一覧には表示しない。

  ここから開いた登録・取込の操作は、保存後に「登録・取込」へ戻る。
  登録フォームとsnapshotのIssue・PR詳細からは、詳細の上部にある「登録・取込へ戻る」で元のパネルを開く。

  登録フォームの未保存入力は、戻ってから開き直しても保持する。
- 作業の「前提作業」で同じプロジェクトの作業を複数選択し、依存を保存する。
  未選択で前提なしにできる。
- 作業の「完了条件の編集」で条件を追加、変更できる。
  同じ文の確認状態を保持し、新しい条件は未確認にする。
  条件未登録の作業は完了として保存しない。
- 未確認の作業は「未着手として確認」を押してから開始する。

- 選択したプロジェクトの「自分の作業」「イテレーション」のタブで画面を切り替える。
  左右の矢印キーでも切り替えられる。
  選んだタブはブラウザに記憶する。
- 「自分の作業」の担当者のボタンで、全員・各担当者・未担当に絞り込む。
  選択はプロジェクトごとにブラウザに記憶する。
  件数だけを示すまとまりは、見出しを押すと展開する。
- 「Issueツリー」で、すべての親子Issueのツリーを開く。
- 目標の見出しにある「目標全体」で、期間をまたぐ進捗と、対象の親Issueのツリー・優先順・変更記録を開く。
- 子Issueを持つ行を押すと、その下のIssueを展開する。
  「内訳を確認」で、対象Issueの進捗と配下の作業を開く。
- 作業の詳細にある階層表示から、上位のIssueへ戻る。
- 一覧の作業名で、成果の根拠・完了条件・状態・待ちを開く。
- 作業の詳細にある「理由・前提を確認」で、着手・継続の判断と関連する前提・後続作業を確認する。
- 目標全体の詳細にある「依存関係」で、進行を止めている作業と、解除に必要な対応を開く。
- 作業の詳細にある「判断待ちの登録」で、判断の名前・選択肢・判断材料・判断する人を入力して判断待ちを登録する。
- 判断待ちを解除するときは、採用する内容と理由を記録する。
- 作業の詳細にある「Estimate（ポイント）」で、保存するEstimateを変更する。
  空欄で更新すると未入力に戻す。
- イテレーションの行を押すと、担当別の負荷と対象作業の一覧をその下に開く。
  複数の期間を同時に展開できる。
  「すべて展開」で全期間の作業を並べ、「すべて閉じる」で集計だけに戻す。
- イテレーション内の目標の見出しで、その目標の作業行を展開・折りたたみする。
  「待ちの理由」の名前で、作業の前提と待ちの理由を開く。
- 「担当別の残り」で担当者名とポイントのボタンを押すと、その担当者の未完了作業を状態別にまとめた担当別一覧を開く。
- 担当別一覧から作業や前提を開いたあとは、詳細の上部にある「担当別一覧へ戻る」で元の一覧を開く。
- 作業の詳細にある「担当者」で、保存する担当者名を変更する。
  空欄で更新すると未担当にする。
- 親Issueのツリーにある「期間の内訳」で、その目標だけのイテレーション一覧を開く。
- 「期限超過 N件」で、終了したイテレーションに残る未完了の作業をまとめて確認する。
- 作業の詳細にある「イテレーションの割当」で、保存する割当を変更する。
  未割当も選べる。
