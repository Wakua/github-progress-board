# 題名の折り返しの検証

開発者が #63 の変更と確認範囲を判断するための記録である。
Codexが2026-11-03、main `160f8e1` と変更後の `88c1e85` を比較した。
実利用者の読みやすさの評価はリリース時に行う。

## 観察と設計

#63は、幅800pxで一覧と詳細を横に並べていた時点のIssueである。
#120で一覧と詳細が単独表示になったため、元の例「会員登録の確認画面で電話番号が消える」は、現在の幅800pxでは1行に収まった。
一方、長い題名「会員登録の確認画面で電話番号を入力して予約一覧に戻り、同じ会員を選んで開くと電話番号が消える」は、最後の「る」だけが2行目になった。

出典は `tests/bug-screens-server.mjs` の架空の予約管理データと変更前のmainである。
通常の19件に、日本語2件・英文1件・空白のない英数字1件を検証時だけ追加した。
一覧で「会員登録」を検索し、題名と対応状況を見て報告を選び、詳細へ進む操作を行った。
これはCodexによる画面操作・自動操作の観察であり、実利用者の行動観察ではない。
今回は画面構造の変更を伴わず、他サービスや操作動画の追加観察は行っていない。

想定する行動は、題名を読んで似た報告かを判断し、必要な報告の詳細を開くことである。
長い題名の末尾だけが別行になる偏りを抑えるため、一覧の題名に `text-wrap: balance` を指定した。
題名の文言、文字サイズ、2行の上限、詳細やかんばんの表示規則は変えていない。
常設の説明も加えていない。
動作条件の正本は[報告一覧と検索](../bug-reporting.md#報告一覧と検索)とする。

幅800pxの再現用の題名は、変更前の45文字・1文字から、変更後の22文字・24文字へ折り返した。

詳細の幅は変更前後とも744pxであり、#63に記録された旧2列表示の約284pxより狭くなっていない。

3行以上の題名は、既存どおり2行で省略され、詳細で本文を読める。

追加8項目はコミット `88c1e85` 上でも実行した。
全体テストと既存ブラウザ検証は、コミット前の同じ製品コードで実行した。
後続コミットは、この文書と検証JSONだけを加える。

再実行時は `PLAYWRIGHT_MODULE` にPlaywrightのモジュール、`CHROMIUM_PATH` にChrome、`QA_ARTIFACT_DIR` に保存先を指定する。
追加ブラウザ検証は、画面用サーバーの `QA_TITLE_WRAPPING=1` を設定して起動する。
変更前の撮影は `QA_PRODUCT_ROOT` をmainのフォルダー、`QA_EXPECT_WRAP` を `previous` として実行する。
いずれも実GitHubへ通信しない。

## 自己レビュー

確認範囲は `160f8e1` と `88c1e85` の差分、一覧・かんばんの題名要素、既存の2行省略と長い文字列の折り返し、題名を返すAPIの72文字上限、検索・詳細・復帰の操作である。
文書は `docs/bug-reporting.md` の「報告一覧と検索」「かんばん」と、#63の完了条件・#59の記録・#120後の表示を照合した。
元の2列表示の列幅を調整する案は使わず、現在の一覧の題名だけに指定した。
既存のCSS指定の繰り返しを検査する単体テストは追加せず、実際の文字の位置と操作をブラウザで確かめた。

指摘として、一覧往復の既存検証が、本文検索の完了前に次へ進む場合があった。
検索語「架空」は全件に含まれるため、件数だけでは応答完了を判別できず、戻った行のフォーカス検査が失敗した。
検索応答の完了を待つように直し、8項目を再実行して成功した。
製品の検索処理は変更していない。

修正後、今回の変更に未修正の指摘はない。
これはCodexの自己レビューであり、別担当によるレビューではない。
UIの判定表は提出PRの「UIレビュー」を正本とする。
