# 報告一覧と詳細の切替の検証

開発者が #120 の変更と確認範囲を判断するための記録である。
Codexが2026-11-03、main `7c4d2c6` と変更後の `5dde82d` を、架空の予約管理の報告19件で比較した。
実利用者の操作評価と、実GitHubへの書き込みは、この検証の対象外とする。

## 観察と設計

変更前の画面で一覧の下部まで移動し、架空の報告 `#101`「予約一覧が更新されない」を選んだ。
広い画面では一覧が左、詳細が右に残り、選んだ後のフォーカスは詳細へ移らなかった。
幅390pxでは詳細から戻ると、一覧を開く前の縦位置987pxから146pxへ移り、選んだ行にもフォーカスが戻らなかった。
出典は `tests/bug-screens-server.mjs` と変更前のmainである。
これはCodexによる実画面の操作と自動操作の観察であり、実利用者の行動観察ではない。
既存サービスの観察と、一覧・詳細を並べない採用判断は [Issue #120](https://github.com/Wakua/github-progress-board/issues/120) を参照する。
今回、操作動画の追加観察は行っていない。

想定する行動は、一覧の題名と状態から報告を選び、詳細の本文や再現データを読み、元の行へ戻って次の報告を選ぶことである。
この行動と採用済みの判断に合わせ、詳細だけを先頭から開き、「← 報告一覧へ」にフォーカスを移す。
戻る際は検索と絞り込みを保ち、一覧の縦位置とかんばんの横位置、選んだ行または札のフォーカスを復元する。
常設の「報告を選ぶと…」という説明と空の詳細欄を削り、題名・対応状況・カテゴリは一覧に、本文・再現データ・更新操作は詳細に残した。
動作条件の正本は[報告一覧と検索](../bug-reporting.md#報告一覧と検索)とする。

## 検証

環境はWindows、Node.js v24.15.0、Chrome 156.0.8078.80。
実行結果と測定したスクロール位置は[検証JSON](120-report-navigation.json)に保存した。
検証はコミット前の同じ製品コードで実行し、コミットまで製品ファイルを変更していないことを差分で確認した。
記録JSONの `checkoutHeadAtRun` は実行時の未コミット作業の基点であり、検証した製品コードの版は `testedProductCommit` で示す。
記録用の後続コミットは、この文書と検証JSONだけを加える。

一覧の往復では、幅1100/800pxで縦位置893px、幅390pxで987pxを復元した。
幅390pxのかんばんでは、横位置401pxをかんばん内に復元し、ページ全体の横はみ出しがないことも確認した。
詳細の更新中に一覧へ戻ると、遅い応答が届いても一覧とURLを保つ。
選んだ報告が対応状況の絞り込みから外れた場合は、一覧の見出しが画面内に表示され、そこへフォーカスが移った。
全ブラウザ検証でページ内のJavaScriptエラーはなかった。

再実行時は、Playwrightのモジュールを `PLAYWRIGHT_MODULE`、Chromeの実行ファイルを `CHROMIUM_PATH`、保存先を `QA_ARTIFACT_DIR` に指定する。
変更前の撮影は `QA_PRODUCT_ROOT` を変更前のmainのフォルダー、`QA_EXPECT_NAVIGATION` を `previous` として追加ブラウザ検証を実行する。
画面操作は、検索「架空」・対応状況「確認完了を除く」→一覧の最下行 `#101`→Enterで詳細→Enterで一覧、の順で行う。

## 自己レビュー

確認範囲は `7c4d2c6` と `5dde82d` の差分、一覧・かんばん・詳細の描画、更新・自動更新・報告送信・対応状況変更の呼出元、URLとフォーカスの扱いである。
文書は `docs/bug-reporting.md` の「報告一覧と検索」「かんばん」「修正後の確認」と、README・仕様書・開発文書の関連参照を照合した。
一覧と詳細の仕様は一か所へ集め、かんばんから参照する形にした。

指摘と修正は次のとおり。

- 狭い画面に残ったグリッドの指定が、かんばんをページ外へ広げていた。
  共通の幅指定へそろえ、横はみ出しと横位置の復元を再検証した。
- 絞り込みから外れた報告から戻る際、見出しへのフォーカスだけでは画面内に表示される保証がなかった。
  見出しへスクロールする処理を加え、対応状況を変更する実操作で確認した。
- 既存ブラウザ検証は、詳細を開いたまま一覧内のカテゴリ設定を操作する前提だった。
  「報告一覧へ」で戻る手順と詳細を開き直す手順へ変更し、16項目を再実行した。
- 追加検証は、短い一覧でも見出しが必ず画面上部180px以内に来ると仮定していた。
  実際の要求である「見出し全体が画面内に見える」に検査を直し、8項目を再実行した。

修正後、今回の変更に未修正の指摘はない。
これはCodexの自己レビューであり、別担当によるレビューではない。
UIの判定表は提出PRの「UIレビュー」を正本とする。
