# リリースと親Issueを折りたたむ操作の検証

[Issue #142](https://github.com/Wakua/github-progress-board/issues/142)の担当者・確認者が、架空データで開閉と日程を確かめるための記録である。
対象は通常のリリース画面で、比較元はmain `f35dcfd`。

## 設計前の観察

Codexが2026-11-01に800px幅のブラウザーでmainを起動し、「リリース」→「計算に使うProject」→「予約管理 開発」を操作した。
Issueツリーには「機能A→実装A・実装B」と「通知→メール通知→配信処理」があった。
同じデータのガントには末端作業が平らに並び、リリース名を押すと計算根拠が開いた。
親の作業だけを隠す入口はなかった。
[変更前のリリース画面](../screens/142/before-01-gantt.jpg)

[Bryntumの公開操作デモ](https://bryntum.com/products/gantt/examples/advanced/)では、最上位の「Launch SaaS Product」の開閉部を押した。
操作前は表示領域に親と配下の行があり、閉じると親だけが残った。
この観察は担当者によるデモの操作で、利用者の行動観察は未実施である。
外部デモの画像はGit管理外に保管した。

## 行動と表示の対応

| 利用者がしたいこと | 見る場所・操作 | 根拠 |
| --- | --- | --- |
| 別の親の作業を探す | 読み終えた親の見出しを閉じ、同じリリースの別の親や独立作業へ移る | 「親子で折りたためないと見にくい」という利用者の指摘と、上記の親子行の観察 |
| リリース同士を比較する | リリース名で日程表を閉じ、見込み・期日・警告を読む | リリースの開閉と要約を残すという依頼 |
| 判断の根拠を調べる | 「計算根拠」または警告を開く。作業名から前提・後続をたどる | 既存のリリース名の操作を観察し、開閉と詳細を別のボタンにした |

親の見出しはIssueのURLを使って構成する。
同じ親が複数のリリースに現れても、開閉状態は別々に扱う。

## 試作での確認

1. [展開時](../screens/142/after-01-expanded.jpg)の作業、進捗率、日程、警告、依存線を記録した。
2. [Aの「機能A」を閉じる](../screens/142/after-02-parent-closed.jpg)と、実装A・実装Bとそれらを結ぶ線が隠れた。結合確認、通知配下、リリースBは操作できた。
   通知・メール通知も個別に開閉し、上の親を開き直しても下の親の状態を保った。
3. [Aのリリース名で日程表を閉じた](../screens/142/after-03-release-closed.jpg)状態で「計算根拠」を開いた。
   [Bの閉じた見出し](../screens/142/after-05-closed-alerts.jpg)からも情報不足の原因を確認できた。
4. 再取得とタブ往復の後、リリースAを開くと「機能A」は閉じたままだった。
   [親も開き直す](../screens/142/after-04-restored.jpg)と元の作業、進捗率、日程、依存線の座標に戻った。

| UIレビューの問い | 判定 | 確認内容 |
| --- | --- | --- |
| I1・I2 情報量 | 確認済み | 親を閉じて配下だけを隠し、リリースを閉じても要約・警告を残す。計算根拠と作業詳細を別の入口から開けた。 |
| J1・J2 判断の手掛かり | 確認済み | 字下げと開閉矢印が親子を示す。初回の画像を見て入れ子の字下げを調整し、320px・開閉文字を2倍にした条件で入口の幅を確認した。 |
| O1・O2 操作 | 確認済み | Enter・Spaceで開閉した。支援技術に公開する開閉状態と制御対象を確認し、再取得時に操作中のリリース見出しへフォーカスが戻った。 |

日・週・月を変更しても、対象作業の進捗率・日程とリリースの要約が一致した。
閉じた親の配下も後続の詳細から選択でき、Escapeで元の作業へ戻った。
この検証はブラウザーでの操作とアクセシビリティ情報を対象とし、実機の音声出力・利用者の独力操作は未確認である。

## 再実行

ローカルでは `node tests/gantt-review-server.mjs 4422 . collapse` を起動し、`http://127.0.0.1:4422/qa` の「QAデータを準備して開く」を押す。
「計算に使うProject」で「予約管理 開発」を選ぶ。
回帰検査は[ブラウザー検証の環境](../development.md#検証手順)を用意し、`QA_BASE_URL`に起動済みサーバーを指定して `npm run test:browser:gantt-collapse` を実行する。
