# 画面の変更前後の画像

画面を変えるPRでは、変更前後の画像をPRの上で確認できるようにする。画像はリポジトリに保存する。容量とパスの問題を避けるため、次の規則を守る。検査方法は[検証手順](development.md#検証手順)を参照する。

## 保存の規則

- 保存先は `docs/screens/<Issue番号>/` とする。フォルダー名は対応するIssueの番号（半角数字）にする。
- ファイル名は `before-01-<名前>.jpg` または `after-01-<名前>.jpg` の形にする。名前は半角の英小文字・数字・ハイフンだけにする。日本語、スペース、大文字は使えない。
- 形式はJPEG、幅は800ピクセル以下にする。
- 1枚は150KiB以下、1つの作業（フォルダー）は合計1MiB以下、`docs/screens/` の全体は30MiB以下にする。

## 容量の考え方

- 画像は、ファイルを削除しても過去の履歴に残る。履歴を書き換えると、コミットのSHAで固定した過去のPRの画像が見えなくなるため、履歴は書き換えない。
- そのため、[全体の容量上限](#保存の規則)は今あるファイルの容量を対象とし、画像に使える総量とみなす。古い画像を削除しても、履歴の容量は減らない。
- 上限に達したら、画像を消して空きを作らず、保存先を変えるかをユーザーが判断する。
- 容量を使い切らないために、PNGや大きな画面全体の画像は保存せず、必要な部分だけを撮る。

## 写してよい画面

- 架空のサンプルデータ（`samples/`、`dist/github-snapshot.json`、テストのfixture）を表示した画面だけを保存する。
- 公開の可否は[公開対象](development.md#公開対象)、他社サービスの観察記録の保存先は[UI設計の規則](../AGENTS.md#ui設計)に従う。

## 撮り方

- 画面幅を[保存の規則](#保存の規則)に合わせて撮る。Playwrightなら、その幅のビューポートで `page.screenshot({ path, type: 'jpeg', quality: 60 })` を使う。撮影後に容量も確認する。
- 変更前の画像は、変更を入れる前のmainで撮る。変更後の画像は、PRのブランチで撮る。同じデータ・同じ画面の幅・同じ操作の後で撮り、違いが変更によるものと分かるようにする。

## PRへの貼り方

PRの本文では、コミットのSHAを含む絶対URLで画像を貼る。ブランチ名を使ったURLは、マージ後にブランチを消すと404になるため、使わない。

```markdown
![変更後：要対応の一覧](https://raw.githubusercontent.com/Wakua/github-progress-board/<コミットのSHA>/docs/screens/<Issue番号>/after-01-attention.jpg)
```

`<コミットのSHA>` は、画像を含むコミットの全長のSHAを使う。リポジトリ内の文書からは、相対パス（例：`screens/5/after-01-attention.jpg`）で参照できる。

画像には、何を撮ったか（画面・データ・操作）と、確認できなかった操作を文章で添える。
