# UI/UXレビューの手順

画面の追加・変更を担当する人とAIが、提出前の問題を見つけ、修正と再確認の根拠を残すための手順である。
配置・表示・文言・操作の流れを変える試作も対象とし、この手順で提出の可否を判断する。
製品の仕様や画面案の採用は、このレビューだけでは決めない。

## 参照する規則

画面の情報量は[方針](../AGENTS.md#方針)、観察と試作は[UI設計](../AGENTS.md#ui設計)、画像は[保存の規則](screenshots.md)に従う。
共通の学習メモは`%USERPROFILE%/Documents/AI-Shared/ui-ux/README.md`を索引とする。
原則や数値基準はここへ転記せず、記録から参照する。

## 確認の進め方

1. 対象の版、画面・状態、表示条件を決める。
   利用者の目的、判断に必要な情報、次の操作を画面の箇所に対応させる。
2. 学習メモのREADMEと01〜03を読む。
   調査・テスト、分類・文言、グラフ・数値表示に関係する変更では、04・05・06の該当節も読む。
   参照した節の「設計で確認する問い」を記録し、対象外の分野には理由を添える。
3. 次の3項目と、変更に関係する問いを実画面で確かめる。
   情報量、判断の手掛かり、操作は別々に判定し、一つの確認でほかも合格にしない。
4. 指摘を修正し、同じ条件で再確認する。
   追加・修正した箇所だけでなく、影響する画面全体で重複と操作のつながりを見直す。

| 項目 | 確認すること | 残す根拠 |
| --- | --- | --- |
| 情報量 | 常設する文や表示を減らせるか。説明を削除・詳細へ移した画面を比較し、その場で必要な情報が残るか確かめる | 削除・移動した情報と、残す情報がどの判断・操作に必要か。変更前後の画像 |
| 判断の手掛かり | 対象・状態・関係と、次の操作への入口が画面に示されているか。色だけで意味を区別させていないか | 利用者の目的に対して見る箇所と、その表示から読み取れる事実。利用者の理解が未確認なら、その区別 |
| 操作 | 必要な操作を実行でき、詳細から戻っても続けられるか。変更に関係する表示条件やキーボード操作でも確認する | 操作前後の画面、手順、結果。選択状態やフォーカスなど、続きの操作に必要な状態 |

情報量の確認を「詳細を開けるか」に置き換えない。
同じ目的の説明の重複と、文字・記号・色など役割が異なる表示を区別する。
文字数は削減量の記録に使い、必要な情報を隠したり、使いやすさの合格基準にしたりしない。

原則の名前や学習メモの仮想例だけを、画面が使いやすい根拠にしない。
静止画での点検、実操作の成功、実利用者の理解は分けて記録する。
このレビューは、既存の観察、利用者による確認、ブラウザ検証に代わるものではない。

## 提出の判定

画面案を利用者へ提出する前と、PRをReadyにする前に、作業担当が対象版の記録を残す。
各項目は「確認済み」「要修正」「未確認」「対象外」で判定し、根拠か対象外の理由を添える。
同じ版の記録は参照してよいが、変更箇所と影響する操作は再確認する。

次のいずれかがあれば、レビュー完了やUI変更の完了を報告せず、PRをReadyにしない。

- 必要な資料を読めない、またはレビュー記録がない。
- 変更の目的や規則に反する指摘が未修正である。
- 今回の変更に必要な確認が未実施である。
  重複・不要な常設説明の点検を「利用者の理解は未確認」に含めて先送りしない。

利用者の理解を確かめるための試作は、上記の条件を満たしたうえで、未確認の仮説と確認課題を添えて提出する。
操作場所や正解を教えずに確かめる課題は、学習メモ04の「ユーザビリティテストの課題設計」「観察と誘導の区別」に従う。
点検の完了を、利用者の理解、画面案の採用、WCAGへの適合が確認できたこととして扱わない。

## 記録の書式

記録は対応するIssue・PR、または既存の画面検討文書の一か所に置き、ほかから参照する。
次の順序で書き、確認結果の長い説明や画像を複数の文書へ写さない。

### 確認範囲

- 対象版、画面・状態、表示条件。
- 利用者の目的 → 判断に必要な情報 → 次の操作。
- 参照したファイル・節・問い、対象外の分野と理由。

### 指摘

| 項目・問い | 判定 | 画面上の根拠・操作・影響 | 対応と再確認 |
| --- | --- | --- | --- |
| 情報量 |  |  |  |
| 判断の手掛かり |  |  |  |
| 操作 |  |  |  |

変更に関係する問いは行を加える。
指摘がない場合も、確認した根拠を記す。

### 未確認の範囲

未修正の指摘と未実施の確認について、理由、影響、次に確認する方法を記す。
最後に、提出できる範囲と、判断を保留する範囲を示す。
